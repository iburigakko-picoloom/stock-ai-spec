# アプリ入力と本人の保有を使う研究比較

2026-10-15。`ops compare-personal`とローカルAPIは、PC取込済みの最新アプリ入力、最新保有台帳、最新原予測、記録済み約定を読み、口座別のHOLD比較へ接続する。入力を台帳へ自動適用せず、全記録を読み直して途中変更があれば結果を拒否する。現在は研究用で、採用・実用推奨・注文を許可する経路ではない。

## 照合するもの

- アプリの各口座と台帳bucketを明示的に1対1対応させ、双方の全口座を含める。口座区分・源泉徴収、現金、全保有の株数・平均取得単価を照合する。同一銘柄の複数口座保有も分離し、単元未満保有を削除しない。4桁/5桁コードを黙って変換しない。
- `cash_basis`で、手入力現金が予約額を含む総額か、予約額控除後の余力かを指定する。予約現金を使い込まず、口座間の現金を転用しない。
- 年内実現益/損・本人入力の繰越損失・NISA枠を省略不可の補足入力として受け、台帳と完全一致させる。nullを0へ補完しない。NISA購入には年間/生涯の残余購入枠が必要で、両者の小さい方を同じ口座の全購入で共有する。売却で同日購入枠を増やさない。
- 記録済みの未反映約定、未解決のOPEN/部分約定、適用済みIDの証拠欠落、予測後の約定を理由付きで停止する。古いOPEN記録を勝手に取消済み・失効済みとは扱わない。状態の照合・修正経路は別途必要。
- サーバー/CLIの現在時刻で最新性を判定する。予測は当日11:30 JST、入力・台帳はその時点以前、原予測生成は確認時刻以前。市場観測時刻/利用可能時刻と全保有を含む価格・銘柄・流動性を確認する。許容経過時間を明示（1〜120時間、CLI既定72時間）。古い過去予測に現在保有を結合しない。

## 費用・税・投資上限

補足JSONの`PersonalSettings`は版、口座対応、現金/投資上限の意味、見直した最大下落率の希望、税状態、費用/税/判断policyを持つ。既存policy IDと台帳の一致を要求する。NISAは`nisa_capacity_basis=remaining_purchase_notional_no_same_day_sale_restore`で残余購入金額という意味を明示する。入力した最大下落率は記録・一致確認に使い、重みへ自動変換したり最大損失の保証にしたりしない。リスクpolicyの実証・本人による最終設定は未完。

投資上限の解釈は`maximum_total_equity_market_value`を明示し、全口座合計の目標株式時価へ適用する。保有がすでに上限超過なら、HOLDを比較対象として残し、上限を超える代替案は総時価が厳密に減るものだけ許す。費用・税・期待値からHOLDが選ばれる場合は超過を明示し、強制売却や台帳書換えはしない。現金や資産額自体を上限額へ切り詰めない。

既存Decision Engineの0/0/1・リスク20日を用い、費用・税の推定を一度だけ控除する。全保有と原予測の全候補を口座別に評価する。探索上限超過は候補を無断削除せず停止。日足参考価格、売却後余力、税丸め、企業行動等の実市場根拠は別の未完項目であり、この研究計算を実約定可能性の証拠とはしない。

## 実行と記録

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe -m stock_ai ops compare-personal --database data/operations/stock-ai.sqlite3 --output <新規JSON>
.venv/Scripts/python.exe -m stock_ai ops compare-personal --database data/operations/stock-ai.sqlite3 --input <補足設定・市場JSON> --output <新規JSON>
```

入力省略時も、現在の不足理由を取得できる。入力JSONは`settings`、`market`、`maximum_input_age_hours`を持ち、構造は`PersonalComparisonRequest`のschemaに従う。確認時刻は実時計から設定する。出力先は上書き拒否。CLI/APIは最新の原記録をDBから読み、外部JSONで保有台帳や原予測を差し替えない。

- `GET /api/v1/personal/readiness`：不足理由を読み出す。
- `POST /api/v1/personal/compare`：明示した補足条件で研究比較。既存のloopback/same-originと`X-Stock-AI-Intent: manual-record`を使用し、bodyの確認時刻はサーバー時計に置換する。約定/現金/税/提案の保存操作は行わない。

正本はcontent ID付きJSON。原入力版・台帳ID・予測snapshot ID、入力一式のhash、補足条件、実装hash、停止理由またはHOLD比較を保持する。原予測snapshotを参照する比較の`DailyDecisionAudit.source_report_ids`は空とし、存在しない開発report IDを生成しない。従来OOFの2つのreport IDはそのまま保持する。

## 確認済みの範囲と残作業

独立手計算で売買各1,000円費用・2,000円推定税・残現金196,000円・HOLD比26,000円を照合した（合成試験専用）。複数口座の共通投資上限、NISA売却で枠を回復しない条件、予約現金、単元未満保有、未反映約定、原記録不変、途中変更拒否、APIの時計/手動意図を検証した。

本人の実入力は保有なし・口座0・資金/リスク未入力。実際のDBを照合し、推奨を生成せず、不足理由を返し、全DB記録のhashが処理前後で一致した。本人の数値を仮置きしていない。

アプリ上の補足費用/税/リスク設定・初回台帳の明示照合と確定、比較結果のクラウド同期/表示、最新推論、実市場NAV、最終selection/holdoutと採用証拠は残る。既存の入力画面とPC取込は利用できるが、このPC/API接続だけで個人向け推奨の完成とはしない。実注文なし。
