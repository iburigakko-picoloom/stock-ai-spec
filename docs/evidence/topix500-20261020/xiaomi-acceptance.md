# TOPIX500方式のXiaomi一括受入

この票は新方式の候補APKについて使う。既存0.1.23の受入票・APKを置き換えず、CIと候補の版/署名/hashが確定してから実施する。現時点で本人端末の成功は未確認。正式モデル採用はHOLD。

| 記録項目 | 本人の記録 |
| --- | --- |
| APK版・code・hash | 未確定／候補作成後に記入 |
| Xiaomi機種・Android・HyperOS | 未確認 |
| 試験日・モデル版・データ最終日 | 未確認 |
| 端末のScaleCat対象数・全保有数 | 未確認（500へ合わせない） |
| 初回・同日再表示・翌営業日更新の時間 | 未確認 |
| 結果 | 各手順に成功／未確認／停止理由を記入 |

1. 本人設定・保有・現金・履歴のバックアップを作り、本人管理PCにも保管する。署名とapplicationIdが一致する通常候補を上書き更新する。不一致なら止め、uninstall/データ消去で解決しない。更新後に元の口座・保有・履歴・モデル・APIキーの設定状態を照合する。
2. 研究用5日/20日bundleと本人入力の確認を11:30までに済ませる。データ・モデル・口座の受領時刻を当日締切へ遡らせない。締切後に初めて入力/取得したものは、条件が整う次の営業日に試す。確認済みの契約/ChatGPT設定は変更した場合だけ再確認する。
3. 市場データの「取得範囲・訂正データ・計算の確認」を開き、「予測対象」をTOPIX500へ変更する。対象3区分の実件数と、順位外を含む全保有の追加を確認する。非対応・履歴不足は理由が表示されることを確認し、架空の株数や価格を入力して通さない。
4. 必要な履歴を取得し、初回の共通集計/cache構築から5日/20日予測・保存まで完了させる。開始/終了時刻、表示した対象数、予測できない銘柄の理由を記録する。初回は全市場価格を展開する処理が残るため、PCの再利用時間を端末の初回見込みとしない。失敗/遅延を成功表示にしない。
5. 同日再表示では保存済みの同じ予測が表示されることを確認する。翌営業日は差分受領→予測→保存→通知を確認する。OSによる遅延は時刻と状態を記録し、必要なら既存の手動実行/再開を使う。強制停止中の自動実行や秒単位の定刻保証は条件にしない。
6. 月次の構成変更・訂正の再取得・実際の保有変更が発生した際は、新しいリスト/入力版で再計算されることを確認する。未発生なら未確認と記録する。この受入のための実注文や、本人台帳への合成約定の登録は行わない。
7. 上位20と全保有から手動ChatGPT相談を作り、回答JSONを検算・提案保存する。異snapshot/古い提案/不正JSON/単元・資金などの違反に理由があることを確認する。回答取込後も保有・現金・実約定台帳を照合し、本人が確認した実約定だけを台帳へ反映する。
8. アプリ終了とAndroid再起動後に同じ予測・本人設定・保有・現金・履歴・再開地点を照合する。本人のバックアップで復元を確認する際は、現在の状態も先に保管する。端末容量を故意に埋めない。同じ入力によるPC数値照合は、本人管理PCへ置いた同じ端末backupから行い、画面だけで一致済みとしない。

APIキー・パスワード・口座番号・私有モデル・実データ入りbackupを公開PR/チャットへ貼らない。結果は上の記録項目と手順1〜8を一度にまとめ、未確認を成功へ読み替えない。新方式の通常運用への既定切替は、この受入と必要な端末/CI検証の後に判断する。
