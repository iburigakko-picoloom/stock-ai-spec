# 個人税を含む状態付きNAVの接続条件

2026-10-18、D160。実装契約であり、税引後NAVの完成・本人税額の確定を示す文書ではない。既存の税引前評価と保存予測を再利用し、個人税の準備で税引前比較の着手を待たせない。

## 既存実装との境界

`ml/nav.py`と`ml/daily_strategy.py`は現在`pre_tax`のみ。`decision/tax.py`は判断用の推定、`decision/simulator.py`は手動実約定の時系列反映であり、受渡基準の年間取引報告書や同日取引の夜間税務取得費を再現するものではない。D157のJST統一・NISA実購入額の一回減算を、完全な年次税会計へ読み替えない。

税引後戦略は、判断時点の現金・保有・税状態から同じDecision Engineを呼び、実際の仮想部分約定・企業行動・受渡し・税支払から次の判断を作る。税前の固定注文列へ最後に税額だけを重ねた結果で代替しない。実台帳・本人設定・原予測は変更せず、同条件のHOLDを別に計算する。

## 時刻と取得費

税の帰属時刻、現金受渡時刻、買付余力の解放時刻を別々に与える。既存`NavSession.sale_cash_available_at`は買付余力の時刻なので、税の受渡日へ自動転用しない。特定口座の受渡日基準は[SBI証券](https://faq.sbisec.co.jp/answer/5eec79e6f93f6b0017a77250/)で確認できる。一般口座の申告上の選択は[国税庁の通達37の10−1](https://www.nta.go.jp/law/tsutatsu/kobetsu/shotoku/sochiho/020624/sanrin/1273_1/37_10/01.htm)に対応する明示的な設定・根拠を要求し、本人の選択を推測しない。日付はすべてJSTで判定する。

特定口座の同日・同銘柄の取得費は、その日の実際の買付をまとめて計算する。売却が先だった場合も含む。[SBI証券の説明](https://faq.sbisec.co.jp/answer/5eba4fbb171ba70012b8fe7f)、[楽天証券の取引ルール](https://www.rakuten-sec.co.jp/web/domestic/stock/rule/surfing.html)。税務上の集計順で実際の現金・約定順を並べ替えない。当日後の約定を11:30の判断へ混ぜず、判明後の会計段階で取得費と残保有の税務簿価を更新する。

買付費用を含む取得費と売却費用の控除は[国税庁1464](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1464.htm)を基礎にする。費用policyとの対応を固定し、実価格に織り込んだ費用を再控除しない。証券会社・手数料コース別の丸めや修正が未確認なら、Decimalの研究用推定であることを明示する。本人の年間報告書との一致とは表示しない。

## 必須入力

| 入力 | 保持する内容 |
| --- | --- |
| 本人状態 | 入力・設定revision、台帳hash、口座区分、当初保有、現金、予約額、取得費、受領時刻 |
| 税policy | 適用期間、口座の帰属日基準、税率と丸め、配当の扱い、口座内/申告上の通算範囲、policy/source ID |
| 税状態 | 期首年内損益・徴収済み額、前年損失の発生年/残額/失効年、申告継続の前提と根拠 |
| 日付 | 約定、税の帰属、受渡、買付余力解放、徴収/還付/納付予定。営業日を推測しない |
| NISA | 当初の購入簿価と経済的取得費の区別、年内残枠・総枠、対象商品の適格性、配当受取方式、年更新の根拠 |
| 企業行動 | 税務上の分類・取得費変更・支払時刻。端数現金や現金交付の税を自動で0にしない |

未入力を0や「適格」へ補完しない。実根拠と開発期間で固定した研究上の仮定を区別し、仮定を本人の申告・税務資格の確認へ昇格しない。後から受け取った税状態や確定申告結果を過去の判断へ遡及しない。

## 現金・年次処理

申告上の税額推定、実際の源泉徴収、口座内還付、申告後還付を別に記録する。[国税庁1476](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1476.htm)の通算条件を口座metadataへ結び付ける。還付の買付余力反映と受渡が異なる場合もあるため、[SBI証券の例](https://faq.sbisec.co.jp/answer/5eec7395f93f6b0017a771f9/)を全口座共通の既定日へ転用しない。金額は各戦略の実約定から計算し、別戦略の実績税額を使い回さない。

推定還付を即時現金へ足さない。未納税・徴収予約・未収金からの徴収を一度だけ扱い、現金・予約・未収金・税債務の恒等式を検査する。支払後の現金NAVと、未納税等を含む推定NAVを分ける。期末の未実現益へ自動売却税を課さず、強制清算の感度は別に出す。税支払資金が不足する場合は理由付きで停止し、外部入金や借入を作らない。

損失繰越は発生年ごとの残額・適用期限・申告条件を保持する。[国税庁1474](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1474.htm)を基に、NISA損失を通算せず、集約された現在の繰越額を年ごとに永久複製しない。年をまたぐ受渡し、無売買年、失効を明示的に処理する。

NISAの枠は実際の購入額で減らし、経済的取得費へ加えた手数料を購入枠へ重ねない。売却後の簿価による総枠の再利用は翌年以後の処理とし、年内枠の即時復活や未使用年内枠の繰越を作らない。[金融庁](https://www.fsa.go.jp/policy/nisa2/know/index.html)。年更新の規則・適格性・当初簿価が不足すれば、その範囲を完了扱いにしない。

## 実装順と受入

1. 実約定から同日取得費・売却損益・残保有簿価を作る会計部品を追加する。既存の税前会計や手動実台帳を先に書き換えない。
2. 税帰属時刻、徴収/還付/納付、年次繰越・NISA簿価を因果的な会計へ接続する。
3. 各判断時点へその時点の税状態と実際の買付可能現金を渡し、同じHOLDと比較する。固定注文の再現も確認する。
4. 保存予測・市場根拠・本人状態・policy/実装hash・全明細を不変receiptへ保存する。実市場と最終採用の既存gateは維持する。

独立手計算で、売買の費用、部分約定、税引後資金による翌日の買付変更、未知の還付日、年をまたぐ受渡し、損失の利用/失効、NISA再利用、配当、端数現金、未来情報の変更不変を検査する。同日取得費の合成例は、期首300株/700円、200株を900円で売却した後に100株/800円を購入し、平均725円・譲渡益35,000円・残200株/725円を期待値とする。現金の実際の順序は保持する。

現時点はこの接続と検証が未完。税引前の実市場比較、18候補/単純戦略/ensemble、開発条件固定・単回holdout・本人レビュー・実機検証も、それぞれ元の完了条件で進める。実売買は行わない。
